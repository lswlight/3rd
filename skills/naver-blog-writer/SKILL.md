# 네이버 블로그 글 작성

목표는 **복사해서 네이버 스마트에디터에 붙여넣으면 바로 발행할 수 있는 글**이다.
네이버 블로그 글쓰기 API는 종료됐으므로 자동 발행은 하지 않는다. 발행은 사용자가 직접 한다.
모든 결과는 한국어로 쓴다.

## 0. 모드 판단

| 입력 | 모드 |
|---|---|
| 키워드, 주제, 메모, 경험담 | **A. 키워드 정보성 글** |
| 종목명·티커·코인 이름, "시황", "차트", "볼린저" | **B. 주식·코인 시황/차트 글** |
| "연예 뉴스", "오늘 핫한 이슈", "화제 뉴스" | **C. 연예 이슈 글** |

둘 다 해당하면 B로 쓰고 키워드를 제목과 본문에 반영한다.
선택 정보(묻지 말고 기본값으로 진행): 글 길이(기본 1,800~2,500자), 말투(기본 친근한 해요체), 블로그 주제/타깃.

## A. 키워드 정보성 글

1. 메인 키워드 1개와 연관 키워드 3~5개를 정한다. 웹 검색 도구가 있으면 최신 정보와 사실을 확인하고, 수치·날짜·출처를 본문에 쓴다. 검색할 수 없으면 확인되지 않은 수치는 쓰지 않는다.
2. `references/naver-seo.md` 의 규칙대로 쓴다.
3. `references/post-templates.md` 의 **A 템플릿** 구조를 따른다.

## B. 주식·코인 시황/차트 글

### B-1. 데이터 수집 (위에서부터 시도)

1. **스크립트** (코드 실행이 될 때):
   ```bash
   python3 <이 스킬 폴더>/scripts/market_data.py KRW-BTC          # 업비트 코인
   python3 <이 스킬 폴더>/scripts/market_data.py 005930.KS        # 코스피 (코스닥은 .KQ)
   python3 <이 스킬 폴더>/scripts/market_data.py NVDA             # 미국 주식
   python3 <이 스킬 폴더>/scripts/market_data.py KRW-ETH --interval 240   # 4시간봉
   ```
   - 종목명만 받으면 티커로 바꿔서 넣는다 (비트코인 → KRW-BTC, 삼성전자 → 005930.KS, 엔비디아 → NVDA).
   - 볼린저 밴드(20, 2), %B, 밴드폭과 스퀴즈 여부, 밴드 이탈 이벤트, RSI, 이동평균, 거래량 배수가 나온다.
   - `NETWORK_BLOCKED` 이면 오류 문구를 그대로 보여 주고, claude.ai의 코드 실행 네트워크 설정에 `api.upbit.com`, `query1.finance.yahoo.com` 을 허용해야 한다고 안내한 뒤 2번으로 넘어간다.
2. **시세 커넥터**: CoinGecko(`get-coin-market-chart`), CoinMarketCap, 미국 주식 정보(`UsStockInfo-get_historical_stock_prices`) 같은 도구가 보이면 최근 60봉 이상의 일별 종가를 받는다. 코드 실행이 되면 `date,open,high,low,close,volume` CSV로 저장해 `--csv` 로 넘긴다. 코드 실행이 안 되면 같은 지표를 직접 계산한다 (20일 평균 ± 2 × 표준편차, %B = (종가 − 하단) / (상단 − 하단)).
3. **사용자 제공**: 위 방법이 모두 안 되면 차트 캡처를 달라고 한다. 캡처에서 읽은 값에는 "(차트 캡처 기준)"이라고 표시한다.

### B-2. 테마·글로벌 상황

웹 검색 도구가 있으면 최근 1주일 뉴스를 확인한다: 금리·환율·달러 지수, 미국 지수와 반도체, 관련 테마, 코인이면 ETF 자금 흐름과 규제 이슈. 확인한 사실만 날짜와 함께 쓴다. 검색이 안 되면 이 섹션은 짧게 쓰고 "최신 뉴스 확인 필요"라고 적는다.

### B-3. 작성

- `references/post-templates.md` 의 **B 템플릿** 구조를 따른다.
- 볼린저 밴드 해석은 `references/bollinger-guide.md` 의 표현을 쓴다.
- 숫자는 스크립트나 커넥터 값만 쓴다. 지어내지 않는다.
- 매수·매도를 권하지 않는다. "상단 돌파 시 ○○, 중심선 이탈 시 ○○"처럼 **조건부 시나리오**로 쓴다.
- 글 끝에 면책 문구를 넣는다: "이 글은 개인 공부 기록이며 투자 권유가 아닙니다. 투자 판단과 책임은 본인에게 있습니다."

## C. 연예 이슈 글 (하루 1개)

### C-1. 뉴스 고르기
1. 웹 검색으로 최근 24시간 연예 뉴스를 찾는다. 검색어 예: "연예 뉴스 오늘", "실시간 연예 이슈", "<오늘 날짜> 연예", 네이버·다음 연예 랭킹, 주요 연예 매체(스포츠 신문, 연예 전문 매체).
2. 후보 3~5개를 뽑고 아래 기준으로 가장 화제인 1개를 고른다.
   - 여러 매체가 동시에 보도했는가 (3곳 이상 우선)
   - 소속사·방송사 공식 발표나 당사자 확인이 있는가
   - 블로그 검색 수요가 있을 만한가 (컴백, 드라마·예능 시청률, 열애·결혼 공식 발표, 시상식, 캐스팅 확정 등)
3. **쓰지 않는 뉴스**: 확인되지 않은 열애설·루머, 사건·사고 피의자 실명, 사망·자살(보도 권고 기준 위반 위험), 미성년자 사생활, 악플을 부를 만한 외모·사생활 평가.

### C-2. 작성
- 기사 문장을 그대로 옮기지 않는다. 사실만 가져와 내 말로 다시 쓰고, 매체 이름과 날짜를 밝힌다 ("○○일 ○○ 보도에 따르면").
- 공식 입장이 있으면 짧게 요약하고, 없으면 "공식 입장은 아직 없다"고 쓴다. 추측성 표현("~라는 소문", "~인 듯")은 쓰지 않는다.
- 구조: 한 줄 요약 → 무슨 일인지(사실) → 배경(이전 활동·작품) → 반응(수치가 있는 것만: 시청률, 음원 순위, 조회수) → 내 생각 2~3문장 → 앞으로 볼 일정.
- 분량 1,200~1,800자, 이미지 자리 2~4개. 기사 사진과 방송 캡처는 저작권 때문에 쓰지 않는다. 공식 SNS 게시물 임베드나 직접 만든 이미지(요약 카드, 일정표)를 권한다.
- 본문 뒤에 **출처 기사 링크 목록**(본문 밖)과 **선정 이유**(후보와 고른 이유 한두 줄)를 붙인다.

### C-3. 이미지
- **요약 카드 (직접 제작)**: 코드 실행이 되면 `scripts/make_card.js` 로 표지 카드와 핵심 요약 카드(1080×1080 PNG)를 만든다.
  ```bash
  node <이 스킬 폴더>/scripts/make_card.js card.json out   # out/cover.png, out/summary.png
  ```
  card.json: `date`, `category`, `headline`(줄바꿈 `\n`, 최대 2줄), `sub`, `points`(핵심 사실 3개, 각 25자 이내), `footer`, `source`, `theme`(rose 결혼·열애 / mint 컴백·음원 / navy 드라마·영화 / sunset 예능·시상식).
  만든 이미지를 열어 글자가 넘치지 않는지 확인한다. 카드에는 확인된 사실만 넣는다.
- **관련 이미지 후보**: 내려받거나 다시 올리지 않고 링크와 저작권 메모만 적는다. 공식 SNS 게시물(네이버 SNS 임베드 가능) → 소속사·방송사 보도자료 사진 → 기사 사진(저작권은 언론사) 순서로 찾는다. 사용 여부는 사용자가 판단한다.

## 출력 형식 (공통)

네이버 에디터는 마크다운을 인식하지 못한다. 본문 블록 안에 `#`, `**`, `-`, 표 문법을 쓰지 않는다.
아래 순서로 출력한다.

1. **제목 후보 3개**: 메인 키워드를 앞쪽에, 30자 안팎으로.
2. **본문**: 코드 블록(```) 하나에 넣어 한 번에 복사할 수 있게 한다.
   - 소제목은 `【 소제목 】` 형태로 쓴다. 에디터에서 '소제목' 서식을 적용할 자리다.
   - 문단은 2~3문장, 문단 사이에 빈 줄을 넣는다.
   - 이미지 자리는 `[이미지: 무엇을 찍은/캡처한 사진인지]` 로 표시한다. 3~6개.
   - 강조할 문장은 `▶` 로 시작한다.
3. **태그**: `#태그` 형식으로 10개 안팎, 한 줄에.
4. **발행 전 체크**: 대표 이미지 추천, 이미지 자리마다 넣을 자료(차트는 업비트나 TradingView에서 볼린저 밴드를 켜고 캡처), 사실 확인이 필요한 부분.

사용자가 파일을 원하거나 Claude Code 환경이면 `posts/YYYY-MM-DD-<키워드>.txt` 로도 저장한다.

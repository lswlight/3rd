# 그믐: 달을 훔친 자 · 기획 7. 기 모으기·타격감·판정·필살기 화질

대상 코드: `game/geumeum/dokkaebi-shooter.html` (커밋 2d57084)

사용자 요청:
1. 기를 모으는 동안에는 기본 공격이 나가지 않아야 한다.
2. 캐릭터마다 모으기 공격 모양이 다른데, 맞아도 효과 없이 그냥 통과한다. 캐릭터마다 다른 맞는 효과를 넣는다.
3. 대장과 캐릭터의 맞는 영역(판정)이 너무 작다.
4. 필살기를 쓰면 화질이 떨어진다. 올릴 수 있는지 검토한다.

---

## 1. 기 모으는 동안 기본 공격 멈추기

### 원인
`updatePlayer()` 의 `if ((keys.fire || touch.down || touch.auto) && P.fcd <= 0) fire();` 가 `keys.charge` 와 상관없이 돕니다. 따라다니는 도깨비불(`P.fam`), 동료 지원 사격(`updateBuddy` 의 `firing`)도 같습니다.

### 바꾸는 안
- 본체 기본 공격: `keys.charge` 가 눌려 있으면 `fire()` 를 부르지 않습니다.
- 따라다니는 도깨비불: 같이 멈춥니다(모으는 동안 화면이 조용해져야 "모으는 중"이 느껴짐).
- **동료 지원 사격은 계속** 쏩니다. 모으는 동안 완전히 무방비가 되지 않게 하기 위해서입니다.
- 이동 속도: 모으는 동안 **70%** 로 느려집니다(`sp *= 0.7`). 기본 공격을 포기하는 대신 정확히 노리는 시간이라는 느낌을 줍니다.
- 다 모였을 때(`P.charge >= chgT()`): 캐릭터 둘레에 그 캐릭터 색 고리가 한 번 번쩍이고 작은 진동(`G.shake 0.05`)을 줍니다. 지금은 소리(`sfx.ready`)만 있어서 화면만 보는 사람은 알기 어렵습니다.
- 손을 떼는 순간 발사하고, 기본 공격은 **0.15초 뒤**부터 다시 나갑니다(`P.fcd = 0.15`). 모으기 탄이 기본 탄에 묻히지 않게 하기 위해서입니다.

## 2. 모으기 공격의 맞는 효과

### 원인
관통하는 모으기 탄(`pierce`)은 맞았을 때 `burst(s.x, e.y, 2, '#fff', 60)` 하나뿐입니다. 흰 점 2개라 거의 안 보이고, 소리도 없습니다. 그래서 적을 그냥 지나가는 것처럼 보입니다. 터지는 탄(`boom`)만 `explode()` 효과가 있습니다.

### 2-1. 모든 모으기 탄에 공통으로 넣을 것
| 효과 | 내용 | 값 |
|---|---|---|
| 맞은 자리 큰 불꽃 | 맞은 지점에 캐릭터 색 원형 섬광 + 파편 | 고리 반경 = 탄 크기 × 1.5, 0.18초 |
| 적 하얗게 번쩍 | `e.flash` 를 길게 | 0.12초 (기본 탄은 0.07초) |
| 잠깐 멈춤(히트스톱) | 대장·수문장·문지기에 맞으면 게임 전체를 아주 짧게 멈춤 | 0.04초. 같은 탄은 0.25초에 한 번만 |
| 탄이 잠깐 느려짐 | 관통 탄이 적에 닿는 순간 0.06초 동안 속도 35% | "파고드는" 느낌 |
| 피해 숫자 | 맞은 자리에 피해량을 떠오르게 | `float()` 재사용, 노란색, 대장에게만 |
| 맞는 소리 | 캐릭터별 소리 (아래 표) | 같은 소리는 0.06초에 한 번 |
| 밀어내기 | 대장 말고 잔챙이·문지기는 뒤로 조금 밀림 | 12~30px |

### 2-2. 캐릭터마다 다른 맞는 효과
| 캐릭터 | 모으기 공격 | 맞는 효과 (그림) | 소리 | 덤 효과 |
|---|---|---|---|---|
| 한별 | 뚫고 가는 회오리 | 초록 소용돌이 고리가 맞은 자리에서 돌며 퍼짐, 종이 부적 조각이 튐 | 휘익 + 바람 | 잔챙이를 위로 띄워 밀어냄 |
| 달래 | 관통 화살 세 발 | 금빛 X자 섬광, 화살이 지나간 자리에 금빛 줄이 0.3초 남음 | 탁! (꽂히는 소리) | 마지막으로 맞은 적에 화살이 꽂혀 0.5초 뒤 작은 폭발 |
| 무쇠 | 터지는 불망치 | (이미 폭발 있음) 땅이 울리는 큰 진동 + 불꽃 파편 위로 솟음 | 쾅 + 쇠 울림 | 진동 `G.shake 0.3` |
| 탈 도깨비 | 큰 도깨비불 | 파란 불꽃이 튀고, 맞은 적에 푸른 불이 붙음 | 화르륵 | 1.5초 동안 작은 지속 피해 |
| 불가사리 | 굴러가는 큰 쇠공 | 쇳조각 스파크가 사방으로, 바닥에 굴러간 자국 | 쿵, 쇠 긁는 소리 | 잔챙이를 크게 밀어냄 |
| 구미호 | 여우구슬 + 여우불 | 붉은·흰 여우불 꽃잎이 흩날림 | 방울 소리 | 맞은 잔챙이 0.6초 동안 공격 멈춤(홀림) |
| 장승 자매 | 터지는 장승 기둥 | 나무 파편 + 흙먼지 + 초록 기운 | 퍽 + 나무 쪼개짐 | 진동 |
| 설녀 | 뚫고 가는 눈보라 | 얼음 결정이 맞은 자리에 맺혔다 깨짐 | 쨍그랑 | 맞은 적 0.5초 느려짐 |
| 이무기 | 다섯 갈래 물줄기 | 물보라가 튀고 물방울이 떨어짐 | 촤악 | |
| 용왕의 장수 | 뚫는 큰 물결 | 초승달 모양 물결 자국이 남음 | 철썩 | 잔챙이 밀어냄 |
| 쇠 도깨비 | 다섯 자루 관통 칼 | 금속 스파크 십자 + 불티 | 챙! | |
| 두억시니 | 뚫는 검은 달 | 보라색 균열이 맞은 자리에 0.3초 남음 | 낮은 웅 | |
| 도깨비 여왕 | 터지는 금 방망이 | 금빛 폭발 + 엽전이 튀어 떨어짐(줍지는 못함) | 짤랑 + 쾅 | |

- 효과 종류는 `parts` 에 새 모양 몇 개(소용돌이 고리, X자 섬광, 결정, 균열)만 추가하면 됩니다. 나머지는 기존 `burst`, `ring`, `fireball`, `glow` 의 색과 크기만 바꿔 씁니다.
- 코드 위치: `pierce` 맞음 처리(1502줄 부근)의 `burst(...)` 한 줄을 `chargeHit(s, e)` 로 바꾸고, `s.kind` 또는 `s.kc` 로 캐릭터를 구분합니다.

### 2-3. 모으기 탄 자체도 눈에 띄게
- 날아가는 동안 꼬리(잔상)를 남깁니다: 탄 뒤로 같은 그림을 3장, 투명도 0.5 → 0.15로.
- 화면 끝까지 간 관통 탄은 그냥 사라지지 않고 작게 흩어지는 효과를 냅니다.

## 3. 맞는 영역(판정)

### 원인
| 대상 | 지금 판정 | 그림 크기 (게임 화면 기준) | 비율 |
|---|---|---|---|
| 대장 (내 탄이 맞는 곳) | 원 반지름 52 | 높이 약 165, 너비 약 165~200 | 그림의 **약 3분의 1** |
| 수문장 | 반지름 46 | 높이 약 144 | 약 3분의 1 |
| 문지기 | 반지름 30 | 높이 약 132 | 약 4분의 1 |
| 내 캐릭터 (적 탄에 맞는 곳) | 탄 반지름 × 0.6 + 2.5 → 보통 약 5 | 높이 약 105 | 점 하나 |
| 내 캐릭터 몸 부딪힘 | 적 반지름 × 0.7 + 3 | | |

대장 그림 가장자리(팔, 무기, 꼬리)를 쏴도 안 맞으니 "그냥 통과한다"는 느낌과 겹칩니다. 내 캐릭터는 탄막 슈팅 방식이라 일부러 작게 해 둔 것인데, 이 게임은 탄이 아주 촘촘하지 않아서 너무 관대하게 느껴집니다.

### 3-1. 적: 원 대신 타원, 그림 크기에 맞춤
- 대장·수문장·문지기는 원 하나 대신 **타원**으로 판정합니다: 가로 반지름 = 그림 너비 × 0.36, 세로 반지름 = 그림 높이 × 0.40. 대략 그림 몸통과 팔까지 들어옵니다.
- 계산: `((s.x-e.x)/(rx+s.r))² + ((s.y-e.y)/(ry+s.r))² < 1`
- 그림마다 몸이 한쪽으로 치우친 경우(꼬리, 큰 무기)를 위해 `hbox: { rx, ry, ox, oy }` 를 대장마다 덮어쓸 수 있게 합니다. 기본값은 위 비율입니다.
- 대장 체력은 그대로 둡니다. 판정이 커지면 더 자주 맞으므로 대장전이 짧아집니다. 기획 5의 측정으로 다시 맞춥니다(대장전 시간 목표표).
- 개발판에 `?hit=1` 을 붙이면 판정 영역을 선으로 그려 보여 주게 합니다(맞추기 쉽게).

### 3-2. 내 캐릭터: 조금 키우고, 잘 보이게
| 항목 | 지금 | 바꾼 안 |
|---|---|---|
| 적 탄에 맞는 곳 | 탄 반지름 × 0.6 + 2.5 | **탄 반지름 × 0.7 + 4.5** (보통 탄 기준 약 5 → 약 7.3) |
| 몸 부딪힘 | 적 반지름 × 0.7 + 3 | 적 타원 판정 × 0.75 + 6 |
| 흰 점 표시 | 작음 | 반지름 4 → **5.5**, 바깥에 캐릭터 색 테두리 |
| 탄이 스칠 때 | 없음 | 판정 바깥 18 안으로 탄이 지나가면 흰 점이 잠깐 커졌다 작아짐(아슬아슬하다는 표시) |

- 너무 키우면 기획 5의 "처음 도전에 깰 확률" 목표가 내려갑니다. 7.3에서 시작해 측정 기록(죽은 횟수)을 보고 6~9 사이에서 맞춥니다.
- 숫자는 한곳에 모읍니다: `const HIT = { me: 4.5, meK: 0.7, bossX: 0.36, bossY: 0.40 }`.

## 4. 필살기 화질

### 원인 (두 가지가 겹침)
1. **게임 화면 자체가 작게 그려진 뒤 늘어납니다.** 게임은 640×360 화면을 기준으로 그리고, 휴대폰에서는 최대 **2.5배**(1600×900)까지만 키웁니다(`resize()` 의 `coarse ? 2.5 : 3`). 요즘 휴대폰 가로 화면은 2,400~3,100픽셀이라, 1600×900 그림을 다시 1.5~2배 늘려서 보여 줍니다. 평소 게임 화면은 작아서 티가 덜 나지만, **화면 가득 나오는 필살기 그림에서는 흐릿함이 보입니다.**
2. **필살기 영상이 1280×716** 입니다. 이것을 캔버스에 1.04~1.1배로 키워 그리고, 다시 화면 크기로 늘리니 두 번 늘어납니다.

### 바꾸는 안 (효과 큰 순서)
| 방법 | 내용 | 효과 | 부담 |
|---|---|---|---|
| **A. 필살기 영상을 캔버스 밖에서 재생** | 컷인 동안 캔버스 위에 `<video>` 요소를 화면 크기로 겹쳐 띄우고(`object-fit: cover`), 캔버스에는 효과만 그림 | 영상이 한 번만, 기기 화면 해상도로 그려짐. 가장 큰 개선 | 작음. 그리기 코드 일부만 이동 |
| **B. 컷인 동안만 캔버스 해상도 올리기** | 컷인이 시작될 때 배율을 기기 해상도까지(최대 4배) 올리고, 끝나면 2.5배로 돌림 | 그림 컷인(영상 없는 캐릭터)도 선명해짐 | 컷인 2초 동안만이라 부담 작음 |
| **C. 영상을 1920×1080 으로 다시 뽑기** | 지금 1280×716 → 1920×1080 | A와 함께 쓰면 더 선명 | 파일 크기 약 1.8배(지금 영상 13개 합계 약 30MB → 약 55MB) |
| D. 평소 화면 배율 올리기 | 휴대폰 최대 2.5 → 3 | 평소 화면도 조금 선명 | 저사양 폰에서 끊길 수 있음. 측정 후 결정 |

**권장: A + B를 먼저.** C는 A·B를 해 보고도 흐리면 합니다. D는 보류합니다.

- A의 세부: `drawCut()` 에서 `useV` 일 때 `ctx.drawImage(vd, …)` 대신 `vd` 요소에 `class="cutv on"` 을 붙여 캔버스 위(같은 `.stage` 안)에 띄웁니다. 흰 섬광, 기술 이름 띠 같은 효과는 그 위에 얹는 얇은 캔버스나 기존 캔버스를 영상 위로 올려 그립니다. 컷인이 끝나면 숨깁니다.
- B의 세부: `resize()` 에 `boost` 인자를 추가합니다. `G.cut` 이 시작될 때 `resize(true)`, 끝날 때 `resize()`.
- 확인 방법: 같은 휴대폰에서 필살기 장면을 캡처해 바꾸기 전후를 비교합니다.

## 5. Tenkai 방 요청 순서
1. 1번 기 모으는 동안 기본 공격 멈추기 (작은 수정)
2. 3번 판정: 적 타원 판정, 내 캐릭터 판정·흰 점, `?hit=1` 표시
3. 2번 맞는 효과: 공통 효과(2-1) 먼저 → 캐릭터별 효과(2-2) → 탄 꼬리(2-3)
4. 4번 필살기 화질: A → B, 바꾸기 전후 캡처
